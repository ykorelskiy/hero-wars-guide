# Hero Wars — Мета-гайд и советчик по контрам

Интерактивное приложение: разбор топ-команд меты 2026, механики синергий,
контр-пики и советчик "выбери героев врага → получи рекомендацию".

Документ описывает **всю логику** приложения, чтобы его было легко
редактировать вручную или через AI-редакторы кода (Antigravity, Cursor,
Windsurf и подобные) без необходимости разбираться в остальном проекте.

---

## 1. Структура файлов

```
hw-guide/
├── index.html   — разметка страницы, 4 вкладки (views)
├── style.css    — все стили, тёмная тема
├── data.js      — ВСЯ база знаний (герои, команды, советы). Редактируется чаще всего.
└── app.js       — логика: рендер, советчик, модалки, матрица. Редактируется реже.
```

**Golden rule:** 90% доработок гайда — это редактирование `data.js`.
`app.js` трогать нужно только если меняется сама механика работы
приложения (например, добавляется новая вкладка).

## 2. data.js — база знаний

### 2.1 HEROES — список героев

```js
const HEROES = [
  {id:'dante', name:'Данте', role:'Керри/уворот', archetypes:['dodge']},
  ...
];
```

| Поле | Тип | Смысл |
|---|---|---|
| `id` | строка, латиница, без пробелов | Уникальный идентификатор. Используется во всех остальных структурах для ссылки на героя |
| `name` | строка | Отображаемое имя (кириллица ок) |
| `role` | строка | Короткая роль для карточки в советчике («Керри/уворот») |
| `archetypes` | массив строк | К каким командам (`TEAMS.id`) принадлежит герой. Один герой может быть в нескольких массивах, если гибкий (например, Астарот в `dodge`, `karkh`, `twins`, `undead`) |

**Специальный архетип `'counter'`** — используется для героев, которые не
образуют свою команду в гайде, а являются именно контр-пиками (Андвари,
Сатори, Хайди и т.д.). Советчик игнорирует `'counter'` при определении
архетипа вражеской команды, чтобы не путать контр-героя с архетипом.

#### Как добавить нового героя

```js
{id:'newhero', name:'Новый Герой', role:'Роль', archetypes:['dodge']},
```

Просто добавь строку в массив `HEROES`. Если герой должен появляться в
конкретной команде (`lineup`) — дополнительно впиши его `id` в нужный
`TEAMS[...].lineup` (см. ниже).

---

### 2.2 TEAMS — досье на каждую команду

Это главная структура. Каждый объект команды:

```js
{
  id:'dodge',                    // уникальный id, совпадает с archetypes у героев
  tier:'S',                      // 'S' | 'A' | 'B' — влияет на цвет и фильтр
  name:'Критоворот (Dante Dodge)',
  tag:'Уворот + крит',           // подзаголовок в карточке

  lineup:[                       // состав команды, 5 слотов (можно меньше)
    {slot:'Танк', hero:'aurora', key:false},
    {slot:'Керри-уворот', hero:'dante', key:true},
    ...
  ],

  hook:'Короткая фраза для карточки списка команд',

  mechanics:[                    // пошаговая механика — раскрывается в модалке
    {t:'Заголовок шага', d:'Описание шага'},
    ...
  ],

  build:'Текст с порядком прокачки.\nПереносы строк через \\n.',

  counters:[                     // кто контрит эту команду
    {hero:'lyria', why:'Объяснение почему'},
    ...
  ],

  subs:'Текст с заменами по слотам.\nПереносы строк через \\n.',

  pros:['Плюс 1', 'Плюс 2', ...],
  cons:['Минус 1', 'Минус 2', ...],
}
```

#### Разбор полей подробно

**`lineup`** — массив слотов команды. `key:true` помечает **ядро связки**
(отображается золотой подсветкой в карточке и модалке). `key:false` —
гибкие/заменяемые слоты. Поле `hero` должно совпадать с `id` из `HEROES`.

**`mechanics`** — это то, что показывается на вкладке «Механика» внутри
модалки, в виде пронумерованных шагов. Пиши их в порядке срабатывания
цепочки (кто первый кастует → что это триггерит → что происходит дальше).

**`counters`** — **критически важное поле**. Оно используется не только
для отображения на вкладке «Контры», но и **советчиком** (`app.js`,
функция `findRiskyCounters`): если пользователь выбрал героя, который
есть в `counters` рекомендуемой команды, приложение покажет
предупреждение «⚠️ Осторожно». Поэтому `hero` в `counters` должен
ссылаться на существующий `id` в `HEROES` — иначе предупреждение не
сработает.

**`pros` / `cons`** — простые списки строк, без ограничения по длине.

#### Как добавить новую команду

1. Скопируй шаблон объекта выше.
2. Придумай уникальный `id` (например, `'nova'`).
3. Заполни все поля.
4. Если хочешь, чтобы советчик рекомендовал эту команду против
   какого-то архетипа — добавь её в `ADVICE` (см. следующий раздел).
5. Если у героев из `lineup` этой команды ещё нет тега архетипа —
   добавь `'nova'` в их `archetypes` в `HEROES`.

### 2.3 ADVICE — база правил советчика

```js
const ADVICE = {
  dodge:{
    label:'Уворот/крит (Dante-Aurora)',
    desc:'Короткое описание архетипа врага',
    counterTeams:['undead', 'taf'],   // id команд-ответов, по убыванию приоритета
    reason:{
      undead:'Почему undead контрит dodge — конкретный механизм',
      taf:'Почему taf контрит dodge — конкретный механизм',
    },
  },
  ...
  unknown:{ ... }  // обязательная запись — fallback, если архетип не распознан
};
```

Ключ объекта (`dodge`, `undead`, ...) — это **архетип вражеской команды**,
который определяется автоматически (см. `detectArchetype()` в `app.js`).
Он совпадает с `id` из `TEAMS`.

`counterTeams` — упорядоченный список id из `TEAMS`, которые рекомендуются
как ответ. Первый элемент — главная рекомендация, остальные — альтернативы.

`reason` — словарь объяснений, обязательно должен содержать ключ для
каждого id из `counterTeams`, иначе объяснение будет пустым.

**Запись `unknown` обязательна** — это fallback, когда выбранные герои не
дают чёткого большинства по архетипу (например, выбраны 2 героя из dodge
и 2 из orion — ничья).

#### Как добавить правило совета

Если добавил новую команду `nova` в `TEAMS` и хочешь, чтобы советчик
предлагал её против, скажем, `karkh`:

```js
karkh:{
  ...
  counterTeams:['undead', 'dodge', 'nova'],  // добавили 'nova' в конец
  reason:{
    undead: '...',
    dodge: '...',
    nova: 'Почему nova контрит karkh',        // добавили объяснение
  },
},
```

## 3. app.js — как работает логика

### 3.1 Определение архетипа врага

```js
function detectArchetype(){
  // считает, сколько выбранных героев принадлежит каждому archetype
  // возвращает архетип с максимальным числом совпадений
  // если героев с archetype нет вообще — вернёт 'unknown'
}
```

**Важно понимать ограничение:** это голосование по большинству, не
точный анализ команды. Если пользователь выберет 2 героя из `dodge` и
2 героя из `undead` — победит тот архетип, который встретился первым при
сортировке объекта (JS сохраняет порядок вставки ключей, так что на
практике выигрывает архетип героя, который был обработан первым в
`Object.entries`). Если нужна более строгая логика (например, явная
пометка «ничья» и предложение выбрать один из двух вариантов) — дорабатывай
`detectArchetype()`.

### 3.2 Поиск рисков (findRiskyCounters)

```js
function findRiskyCounters(teamId){
  // берёт team.counters для рекомендуемой команды
  // проверяет, есть ли среди ВЫБРАННЫХ вражеских героев кто-то из этого списка
  // если да — возвращает предупреждение
}
```

Это защита от ситуации «советчик предлагает Undead, но враг уже поставил
Данте (хард-контр Undead)» — в этом случае юзер увидит явное
предупреждение с объяснением, а не только слепую рекомендацию.

### 3.3 Матрица контр-пиков (renderMatrix)

Строит таблицу «команда × команда». Логика ячейки:

1. Если `rowTeam` есть в `ADVICE[colTeam.id].counterTeams` → зелёная («выигр.»)
2. Если у `rowTeam.counters` есть герой, чей архетип совпадает с `colTeam.id` → красная («риск»)
3. Иначе → нейтральная («равно»)

Это упрощённая тепловая карта, не полноценный симулятор боя — она
основана на тех же данных, что и советчик, просто в табличном виде.

### 3.4 Рендер карточек и модалки

`renderTeamsGrid()` — рисует карточки на вкладке «Все команды».
`openModal(teamId)` — открывает полноэкранную модалку с 4 вкладками
(Механика / Сборка / Контры / Замены и оценка), данные берутся
непосредственно из объекта `TEAMS`.

## 4. Частые доработки — рецепты

### Добавить героя в существующую команду
→ Правь `TEAMS[...].lineup` в `data.js`. Не забудь добавить `id` героя
  в `archetypes` этого героя в `HEROES`, если хочешь, чтобы советчик
  его учитывал при распознавании архетипа.

### Изменить рекомендацию советчика
→ Правь `ADVICE[archetype].counterTeams` — порядок массива = порядок
  приоритета рекомендаций.

### Добавить новый тир (например 'SS')
→ В `app.js` найди все места с тройным условием
  `team.tier === 'S' ? ... : team.tier === 'A' ? ... : ...`
  (используется в `renderTeamsGrid` и `openModal`) и добавь новую ветку.
  Также добавь цветовую переменную в `style.css` (`--ss: #цвет`).

### Изменить визуальную тему
→ Все цвета вынесены в `:root{}` в начале `style.css`. Меняй переменные,
  не ищи цвета по всему файлу.

### Полностью новый архетип с нуля
1. Добавь героев в `HEROES` (или используй существующих)
2. Добавь команду в `TEAMS`
3. Добавь запись в `ADVICE` — как минимум с самой собой как контром
   какого-то другого архетипа (иначе советчик никогда её не предложит)
4. Обнови `unknown.counterTeams`, если новая команда должна быть
   универсальным fallback-ответом

## 5. Известные упрощения (не баги, а осознанные решения)

- Советчик работает по **тегам архетипов**, а не по реальной боевой
  симуляции. Это база знаний в форме правил, не движок расчёта урона.
- Определение архетипа врага по большинству голосов может ошибаться на
  смешанных/нестандартных командах — это ожидаемо, приложение подсказывает
  наиболее вероятный сценарий, а не гарантированный результат.
- Матрица контр-пиков считается по тем же данным, что и советчик —
  если расходится с реальным опытом игры, значит нужно поправить
  `ADVICE` или `counters` в `data.js`, а не искать баг в `app.js`.

## 6. Проверка перед деплоем

Открой `index.html` в браузере и проверь:
1. Вкладка «Советчик» — выбери 2-3 героя, нажми «Проанализировать»
2. Вкладка «Все команды» — фильтры по тиру работают, карточки открываются
3. Вкладка «Матрица» — таблица отображается без переполнения
4. Консоль браузера (F12) — не должно быть ошибок JS

Если правишь `data.js` через текстовый редактор — проверяй синтаксис
JS перед тем, как открывать в браузере:
```bash
node --check data.js
```
